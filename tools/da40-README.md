# DA40 asset conversion

`da40-convert.mjs` converts the pinned DA40 FlightGear archive and selected FlightGear base-package cockpit parts into `public/models/da40/da40-ng.glb` and `rig.json`. It needs Python 3, Node, and the pinned tooling dependencies. The converter and `test/da40-assets-test.mjs` use the local lock in `tools/da40-tooling` (`npm ci --prefix tools/da40-tooling`); see `DA40-START-HERE.txt` for complete setup, downloading the sources, and tests. The repository's `three` dependency is also used. No files are downloaded by the converter.

Extract the original DA40 source archive from `https://codeload.github.com/sryu1/DA40/tar.gz/0d50a457edb203b9ac6058b41cac1b33922acf28` (SHA-256 `eb8ce8950d7fe7d344012f1635e46d154e9f28496786f08f13699a8da643d64d`, DA40 revision `0d50a457edb203b9ac6058b41cac1b33922acf28`) into `.scratch/da40/source` with its archive's top directory stripped. Add the following paths from `https://gitlab.com/flightgear/fgdata/-/raw/7e1ac500e30645871e55a9c61e441d0763edabd5/` into the same source directory, preserving their paths:

- `Aircraft/Instruments-3d/FG1000/GDU104X/GDU-1040.1.xml`
- `Aircraft/Instruments-3d/FG1000/GDU104X/Model/GDU-104X.1.gltf`, `GDU-104X.1.bin`, `FG1000.png`, `screen.png`
- `Aircraft/Instruments-3d/FG1000/GDU104X/Textures/GDU-104X.png`
- `Aircraft/Instruments-3d/FG1000/GMA1347/GMA1347.xml`, `GMA1347.ac`, `GMA1347.png`

Run `node tools/da40-convert.mjs`, then `node test/da40-assets-test.mjs`. Files under `.scratch/da40` are build inputs/reports, not runtime files. `COPYING` is copied from the aircraft archive; retain `NOTICE.md` with the result and comply with the two source packages' licenses when distributing.

The source AC geometry is converted without polygon decimation; Draco edgebreaker quantizes positions to 16 bits, normals to 12, and UVs to 14. Assimp drops the original AC normals, so `da40-normals.mjs` restores them for selected external airframe components using the source surfaces' smooth flags and crease angles, including across texture-coordinate seams. Flat source surfaces remain flat; the wheels, cockpit mechanisms and other meshes are left untouched. Original texture resolutions are retained: the exterior livery, cockpit placards and G1000 bezel textures use lossless WebP, and other textures use WebP quality 86. Assimp emits AC geometry in `(source X, source Z, -source Y)`, so the glTF root turns -90 degrees about Y, making source `(X,Y,Z)` become browser `(Y,Z,X)`: meters, +X right, +Y up, -Z forward. The independently authored FGData glTF is first rotated -90 degrees about X into the AC basis. Parent XML offsets are preserved as named `da40-instance-*` nodes. Both G1000 screens are original black screen meshes for a simulator to drive, not rendered avionics. Run `node test/da40-normal-test.mjs` to verify smooth, flat and creased surface behavior.

The manifest records source XML motion factors, center/axis or axis endpoints, interpolation and expressions, plus corresponding model-space pivots and normalized axes. Nodes are matched within the indicated instance subtree. Motion is not baked into glTF clips: an integrator must interpret the runtime properties, rule ordering, groups, conditions and overlapping pivots. Visibility selections (including prop-disc versus propeller) are included as unsupported rules with source conditions and require explicit handling. Shader, light, click, property, overlay and procedural logic are not reproduced. Source `air_vent` overlay values are recorded, not evaluated. The Hobbs unit's XML heading/pitch/roll is converted using a heading-pitch-roll quaternion; verify its appearance in-engine. Six external rain and tyre-smoke effect references are intentionally absent.
